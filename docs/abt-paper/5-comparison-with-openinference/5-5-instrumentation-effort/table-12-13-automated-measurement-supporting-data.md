# Tables 12 and 13 Supporting Data: Automated Static Instrumentation-Effort Measurement

This document records the automated measurement procedure used for Tables 12 and 13.

## Measurement Script

The static instrumentation-effort table is generated by:

```text
python .\src\experiments\agent_trace_experiments\instrumentation_effort_measurement.py
```

The script is implemented in:

```text
src/experiments/agent_trace_experiments/instrumentation_effort_measurement.py
```

## Counting Rules

The script applies the following rules:

1. LOC counts non-empty, non-comment Python lines in the instrumentation adapter files.
2. Instrumentation call-site count counts trace-related API or instrumentation-helper call sites detected by AST.
3. API argument count counts explicit information items supplied to trace-related calls.
4. Nested dictionary entries supplied to trace APIs are counted as separate information items.
5. Source-target LOC is used as the denominator for instrumentation code ratio. If the original public source snapshot is not present in the workspace, the script uses the declared source LOC recorded in the evaluation supporting data.

## Interpretation Note

Instrumentation call-site count is not expected to decrease monotonically for every target. Direct OI/Otel instrumentation can place many span-level attributes inside a single span creation call, while ABT may express behavior semantics through multiple behavior-level calls. Therefore, call-site count is interpreted together with LOC and API argument count. In this study, the main effort-reduction measurement is the consistent reduction in instrumentation LOC and explicitly supplied API argument items.
